# Six legacy guard lanes on V2: status, 2026-11-19

**All six lanes are now implemented as opt-in V2 lanes** (`plugin-v2/{preflight,binary,subreport,confab,audit,janitor}.js`, composed by `setup-lanes.js` after the core setup). Each lane is off unless its flag is set to an accepted value; any other value, including V1's `0`/`off`, leaves it off. `TOOLCALL_GUARD=off` disables all six regardless of their flags (stream guard and string scrub stay on). Which lanes were verified live is tracked in the [port queue](v2-port-queue.md).

| Lane / V1 flag suffix (`TOOLCALL_GUARD_`) | V1 default vs. archived evidence | V2 status and exact flags |
|---|---|---|
| Preflight `PREFLIGHT`, `CLAMP` | Log (`1`); rejection requires `block`, timeout injection independently requires `CLAMP=1`. **12 pattern records in log mode, 23 clamps, 1 giant-output record**. Clamping actually ran; no block or binary-peek record. | `execute.before` on `shell`. `PREFLIGHT=1\|log` records pattern/binary-peek rule hits; `block` also refuses the call. `CLAMP=1` (independent) sets `CLAMP_MS` (default 120000) on scan-like commands without an explicit timeout. Records omit the command text. |
| Binary `BINARY` | On unless `0`; **1 suppression**. | `BINARY=1` only. `execute.after` replaces completed text parts whose first 8 KiB contain NUL with a short notice; media parts untouched. Affects model input only: it cannot retract streamed UI output or prevent a spill. |
| Subreport `SUBREPORT` | Log by default; **3 records, all `log`**, none `annotate`. | `SUBREPORT=log\|annotate`. Context hook detects empty/clipped completed child reports (tool result or synthetic subagent message verified against stored context); `annotate` appends a resume hint with the real child session ID to the outbound copy only. Async acknowledgements and cancellations are ignored. |
| JEV confab `SCRUB` | Default `1`: scoped rule logging + adjudication when the decision service is live. **88 tier-1 and 10 tier-2 records**. Tier 2 only logs. Tier 1 can replace reasoning in `strip` mode; records do not establish stripping. | `SCRUB=1\|log` logs tier-1 rule hits; `strip` removes rule-matched plain reasoning parts from the outbound copy, never emptying a message. Scoped by destination model (`SCRUB_PROVIDERS`, default `qwen\|ds4`). Tier-2 classification additionally requires `SCRUB_JEV=1` (numeric-loopback endpoint, rate-limited, verdict logged only). |
| Turn audit `AUDIT` | Default interactive `1`, alternative `overnight`. **302 audit records, 39 `fired`; 302 shadow records**. These are classifications, not confirmed failures or nudges. Shadow comparisons do not identify the selected mode. | `AUDIT=1\|log\|overnight` on `session.execution.succeeded` (threshold 0.5, `overnight` 0.6, `AUDIT_T` overrides). Sending request/reply text to the classifier requires the second opt-in `AUDIT_SEND=1`. `DANGLING=nudge` with `AUDIT=1\|overnight` queues one nudge for deterministic zero-tool dangling stops (main sessions, max 2/session, claim-file dedup); `log` never nudges. |
| Janitor `JANITOR` | On unless `0`; startup sweep of spill files **>1 GB and >24 h old**. No janitor file; V1 logged only on deletion. Neither an override nor an uneventful sweep can be reconstructed. | `JANITOR=1` deletes, `dry` only counts. One bounded sweep per process (cross-process claim, 6 h) of `opencode/tool-output/tool_*` files >1 GB, >24 h, with id/mtime provenance; skips symlinks, hardlinks, foreign owners; never touches shell captures. OpenCode already prunes these after **7 days**, so this only matters under disk pressure. |

**Evidence and limits.** A V1 backup copy of `config/plugins/toolcall-guard.js` has Git blob `2c2eb020`, byte-identical to `816c810:plugins/toolcall-guard.js`; the assessed working file is **different** (changes in stream instrumentation/V2 setup). The V1 wrapper has no guard settings. The six primary flags were unset in the assessment shell; neither fact reconstructs earlier process environments. Archived `data/toolcall-guard.*` counts above are aggregate historical records, not unique incidents, proof of final launch settings, or proof that one plugin revision produced every line.

Source checkout is not proof of installed binary parity.
